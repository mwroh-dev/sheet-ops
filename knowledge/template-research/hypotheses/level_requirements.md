# L1-L5 Promotion Requirements

This rubric governs promotion decisions for template-research artifacts. It is hypothesis-first: Agent B may propose structure and likely capability links, but only Agent A evidence and Agent C judgment can move a template upward.

## Level Definitions

### L1 - Seed hypothesis
- Agent A: provides one observation or one imported template record with basic metadata and a short why/how summary.
- Agent B: drafts a plausible pattern hypothesis and trigger mapping, but may not infer recurrence.
- Agent C: confirms the item is useful as a research seed, not as a promoted pattern.

### L2 - Clustered hypothesis
- Agent A: provides at least two comparable observations from distinct sources or source categories.
- Agent B: identifies shared mechanics, shared wording, or shared layout behavior across the cluster.
- Agent C: judges that the cluster is coherent enough to track as a recurring research target, but still not a supported pattern.

### L3 - Recurring pattern candidate
- Agent A: provides evidence from at least two independent sources with enough fidelity to show the same workflow pattern.
- Agent B: names the pattern, its trigger set, and the likely capability surface it would exercise.
- Agent C: judges that the pattern is likely recurring and worth capability planning, but not yet a release claim.

### L4 - Supported research pattern
- Agent A: provides multiple independent observations plus representative detail showing stable structure, recurring actions, and common validation or workflow mechanics.
- Agent B: supplies a bounded hypothesis with clear triggers, explicit likely existing capabilities, and explicit likely missing capabilities.
- Agent C: confirms the evidence is strong enough for a supported research pattern and the hypothesis is not overfitted to one source.

### L5 - Promotable capability signal
- Agent A: provides robust cross-source evidence, including edge cases or variants that still preserve the same core pattern.
- Agent B: narrows the hypothesis to a capability-ready statement, with triggers that are specific enough to guide implementation and verification.
- Agent C: judges that the pattern is stable enough to inform roadmap, backlog, or contract discussion.

## Role Expectations By Level

### Agent A evidence
- Must stay factual and source-bound.
- Must name the source type, observed structure, and observable behavior.
- Must not claim capability support.

### Agent B hypothesis
- Must translate observations into candidate patterns, triggers, and likely capability touchpoints.
- Must clearly label all outputs as hypothesis unless the evidence threshold is already met.
- Must not use evidence language to imply promotion.

### Agent C judgment
- Must decide whether the evidence and hypothesis together justify a level change.
- Must separate "interesting" from "promotable."
- Must reject promotion if the pattern depends on one narrow workbook style or a single source family.

## Promotion Guardrails

- No level may be assigned solely on category similarity.
- Visual similarity alone is insufficient without stable workflow or data mechanics.
- A hypothesis may be useful without being promotable.
- Evidence and hypothesis must be independently readable: one can verify the observation trail without accepting the inference.
- Promotion should prefer recurring mechanics over domain novelty.
